# История изменений

Перевод [CHANGELOG.md](../../CHANGELOG.md). Источником является английский
текст; при расхождениях действует он.

Формат следует [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
нумерация версий — [Semantic Versioning](https://semver.org/lang/ru/).

## [Не выпущено]

## [0.7.2] – 2026-08-20

### Исправлено
- **Сводка изменений не появлялась при выходе из пробной
  сборки.** То, что работало в прошлый раз, записывалось тремя
  числами и без метки, поэтому 0.7.1-beta.5 и готовая 0.7.1
  оставляли один и тот же след: шаг между ними был невидим, и
  сводка так и не появлялась. Теперь метка записывается, а
  приход к готовой версии считается шагом вперёд, хотя номер
  не меняется. Между двумя пробными сборками с одним номером
  остаётся тихо: списку изменений там нечего сказать.

## [0.7.1] – 2026-08-20

### Добавлено
- **Кнопка обновления заодно ищет новую версию.** Одно нажатие вместо двух. В
  настройках это можно отключить — для тех, кто не хочет обращаться к сети
  чаще необходимого.
- **Настройки расположены в два столбца.** В один столбец окно получалось
  высоким и узким: на экране ноутбука приходилось прокручивать ради настроек,
  которые свободно помещаются рядом.

### Изменено
- Подготовка к пробным сборкам. В повседневной работе этого не видно.

### Исправлено
- **Меню в области уведомлений растёт вместе с содержимым.** У него была
  жёсткая ширина, и строка дополнительного использования в неё не помещалась:
  в ней две суммы и валюта, поэтому она переносилась на вторую строку. В меню,
  где каждая другая строка — это один лимит, перенесённая строка читается
  как две.
- **Исправления перевода.** Шесть языков всё ещё называли дополнительное
  использование «кредитами», хотя число обозначает деньги, и все языки
  утверждали, что непереведённый список изменений показывается на немецком —
  он показывается на английском. Сообщения об ошибках хранилища учётных
  данных Windows были жёстко на немецком; теперь они следуют языку
  интерфейса.

### Безопасность
- Страница выпуска из ответа GitHub теперь проверяется так же строго, как
  адреса загрузки: только https.
- Действия рабочих процессов закреплены за хешами коммитов, а не за
  подвижными метками. Метку может перенаправить тот, кто управляет
  репозиторием действия, хеш — нет. Это важнее всего для стороннего
  действия публикации, которое работает с правом записи в процессе,
  собирающем публикуемый файл.

## [0.6.2] – 2026-08-20

### Изменено
- **Значок в области уведомлений показывает своё состояние.** Без входа —
  серый. После входа и пока всё в пределах — зелёная галочка; с порога
  предупреждения — жёлтый вопросительный знак, с критического — красный

### Исправлено
- **Дополнительный лимит показывался в сто раз больше и не в той единице.** API
  сообщает `used_credits: 2276`, и это не 2276 кредитов, а 22,76 EUR — сумма в
  наименьшей единице валюты. **Валюта берётся из учётной записи** — USD, BRL,
  смотря какая, — и вместе с ней число знаков после запятой, ведь не у каждой
  валюты их два. Теперь читается поле `spend`, которое прямо говорит, что
  означают его числа.

## [0.6.0] – 2026-08-20

### Исправлено
- **Недельные лимиты для отдельных моделей не отображались.** Тот, у кого есть
  лимит Fable, не видел его нигде — ни во всплывающей подсказке, ни в
  контекстном меню, ни в окне подробностей, — хотя сам Claude его показывает.
  Причина: приложение читало поля `seven_day_opus` и `seven_day_sonnet`, где имя
  модели заложено в идентификаторе. Оба теперь пусты, а поля `seven_day_fable`
  не существует.

  API отдаёт те же значения ещё и списком `limits`, где модель названа в
  содержимом (`scope.model.display_name`). Теперь этот список читается в первую
  очередь; прежние поля остаются запасным вариантом. **Любая будущая модель
  появится сама собой**, без изменений здесь. Подробности в
  [docs/api-research.md](../api-research.md).

  Значок в области уведомлений тоже учитывает эти лимиты — прежде он оставался
  зелёным, когда квота модели была уже исчерпана.

### Добавлено
- **Девять языков.** Немецкий, английский, испанский, французский, итальянский,
  португальский (Бразилия и Португалия отдельно), русский и упрощённый
  китайский. При первом запуске приложение следует языку системы; сменить его
  можно в окне установки — там выбор действует сразу и его принимают **обе**
  кнопки — а позже в любой момент в настройках.

  Вместе с языком меняется и культура для чисел, дат и времени: тот, кто
  переключает интерфейс на французский, не ждёт там немецких дат.

  **История изменений тоже переведена.** Сводка после обновления появляется,
  таким образом, на том же языке, что и интерфейс. Источником служит английский
  текст в [CHANGELOG.md](../../CHANGELOG.md); переводы, в том числе немецкий,
  лежат в [docs/changelog/](.).

  Названия продуктов и моделей не переводятся: «Claude UsageChecker», «Claude
  Code» и имя модели из API — «Fable» на любом языке остаётся Fable.
- **Пороги предупреждения и критического уровня настраиваются.** С какой
  загрузки значок становится жёлтым, а с какой красным, теперь задаётся в
  настройках, а не жёстко в коде (значения по умолчанию прежние: 75 % и 90 %).
  Порог предупреждения выше критического отклоняется, а не исправляется молча:
  он никогда бы не сработал.
- **Сводка новшеств после обновления.** При первом запуске новой версии
  приложение показывает, что изменилось с версии, работавшей до этого.
  Пропущенные промежуточные версии включаются. Источник — история, поставляемая
  вместе с программой, без обращения к сети: сводка доступна и без соединения и
  неизбежно показывает состояние, отвечающее запущенной версии. При самом первом
  запуске она пропускается.
- **«О программе Claude UsageChecker» в контекстном меню.** Показывает значок,
  версию, краткое описание и ведёт на страницу проекта. Оттуда же доступна и
  полная история.

### Изменено
- **Язык проекта — английский.** Документация, комментарии, идентификаторы и
  имена тестов — всё в репозитории, кроме немецких текстов интерфейса и уже
  сделанных коммитов. Причина проста: это открытый репозиторий, и тот, кто его
  найдёт, должен суметь его прочитать. Немецкая документация ведётся параллельно
  в [docs/de/](../de/).
- Последняя работавшая версия записывается в файл настроек (`lastRunVersion`).
  Это единственный признак, по которому приложение может распознать обновление:
  сам исполняемый файл не знает, что работало до него.

  Прежние версии этого поля не знали. У того, кто обновляется с такой версии,
  записи нет; тогда решает наличие файла настроек: оно доказывает, что
  приложение уже работало, и показываются новшества текущей версии. Без этой
  ветки именно та версия, которая вводит сводку, не показала бы ни одной.
- `MonitorOptions` больше не содержит пороги. Монитор никогда их не читал: он
  добывает значения, но не оценивает их. Оценка происходит в одном-единственном
  месте, в `TrayIconSeverityResolver`, на основе пользовательских настроек. Два
  места для одного и того же значения были бы приглашением покрутить позже не ту
  ручку.
- Вычисляемый `PollInterval` больше не пишется в файл настроек. Оттуда он
  никогда не читался; он лишь выглядел как второе указание на интервал опроса,
  способное противоречить первому.
- **Окно настроек остаётся на экране.** Оно растёт вместе с содержимым, и его
  размер нельзя изменить; на невысоком экране оно выходило за нижний край
  вместе с кнопкой «Сохранить». Теперь этому мешают две вещи: ряд кнопок
  закреплён под прокручиваемой областью и остаётся виден, каким бы низким ни
  был экран, а окно измеряется после построения и сдвигается вверх, если всё
  ещё выступает. Одного ограничения высоты не хватало: Avalonia центрирует окно
  по той высоте, которая у него есть при открытии, а содержимое растёт потом.

### Удалено
- **Ввод токена вручную** исчез из настроек. Пользы от него не было никому:
  единственный токен, который можно было вставить, выдаёт `claude setup-token`,
  а ему не хватает области `user:profile`, которую требует конечная точка.
  Токены, которые работают, — токен установленного Claude Code и токен
  собственного входа — вручную не набирают. Токен, сохранённый прежней версией,
  по-прежнему читается; исчез лишь способ добавить новый. Обоснование в
  [docs/api-research.md](../api-research.md).

### Документация
- **Шаблоны для сообщений об ошибках и пожеланий** в
  `.github/ISSUE_TEMPLATE/`, а также шаблон для pull request и
  [CONTRIBUTING.md](../../CONTRIBUTING.md) — на английском, чтобы сообщить о
  проблеме можно было и за пределами немецкоязычного пространства. Формы
  спрашивают версию, операционную систему, подписку и источник токена и прямо
  предостерегают от вставки токена.
- Заметки об API ([docs/api-research.md](../api-research.md)) фиксируют новый
  формат ответа, включая поля, которые остаются неиспользованными, и причину.

## [0.5.0] – 2026-08-19

### Изменено
- Целевое расположение установки теперь
  `%LOCALAPPDATA%\Programs\ClaudeUsageChecker` вместо
  `%USERPROFILE%\ClaudeUsageChecker`. Это место, предусмотренное Windows для
  приложений без прав администратора: там же находятся VS Code и Signal. Корень
  профиля пользователя остаётся свободным — там, рядом с документами и
  загрузками, программ никто не ждёт.

  **Уже установленные копии сами не переезжают.** Они продолжают работать со
  старого места. Чтобы переехать, достаточно открыть настройки и сохранить: при
  установленном флажке автозапуска копия отправится на новое место. Старый
  каталог после этого можно удалить вручную.

## [0.4.2] – 2026-08-19

### Исправлено
- Тот, кто пропускал установку при первом запуске, а позже лишь ставил флажок
  «Запускать вместе с Windows», получал запись автозапуска, указывающую на папку

## [0.4.1] – 2026-08-19

### Исправлено
- Папки распаковки прежних версий оставались во временном каталоге. Сжатый
  одиночный файл не может загрузить свои нативные библиотеки из пакета — среда
  .NET распаковывает их в `%TEMP%\.net\ClaudeUsageChecker\<идентификатор>`, а
  поскольку идентификатор зависит от содержимого, каждая версия получала
  собственную папку. Около 16 МБ на обновление, накапливавшихся без предела.
  Теперь приложение убирает их само.

### Документация
- [SECURITY.md](../../SECURITY.md) полностью перечисляет, что приложение и где
  сохраняет и что осталось бы после удаления.

## [0.4.0] – 2026-08-19

### Добавлено
- **Постоянная установка.** Если приложение работает вне своего целевого места,
  оно один раз при первом запуске предлагает скопировать себя в

## [0.3.3] – 2026-08-19

## [0.3.0] – 2026-08-19

Первая версия, способная обновлять себя. Начиная с неё достаточно одного щелчка
— ручная загрузка отпадает.

### Исправлено
- Версии отображаются в трёх составляющих. Четвёртая берётся из версии сборки и
  ничего не значит: «Версия 0.2.0.0 актуальна» только сбивало с толку.

### Добавлено
- **Обновление одним нажатием.** «Установить и перезапустить» загружает новую
  версию, сверяет её сумму SHA-256 с опубликованной, заменяет работающий файл и
  перезапускается. Уведомление, которое нужно отрабатывать вручную, на практике
  так и остаётся лежать.
  - Если контрольная сумма не совпадает или отсутствует, ничего не
    устанавливается и ничего не выполняется.
  - Адрес берётся из ответа GitHub по этому репозиторию; адреса без HTTPS
    отбрасываются.
  - Только после явного щелчка, никогда молча в фоне.
  - Замена использует то, что Windows позволяет переименовать работающий файл.
    Если установка нового файла не удаётся, переименование отменяется.

### Изменено

## [0.2.0] – 2026-08-19

Первый выпуск. Самостоятельный одиночный файл для Windows x64, 21 МБ, среда
.NET не требуется.

### Отображение

- Пятичасовой лимит сессии и недельные лимиты (всего, Opus, Sonnet) из
  `GET /api/oauth/usage` — достоверные значения, а не оценки.
- Подсказка с загрузкой, временем сброса и остатком времени. Если сброс
  приходится на другой день, перед временем стоит день недели; начиная с недели
  — дата: одно лишь время для недельного лимита было бы двусмысленным.
- Контекстное меню со **всеми** сообщёнными лимитами.
- Окно подробностей с полосами выполнения, временем сброса, дополнительными
  кредитами (`extra_usage`) и фактически использованным источником токена.
- Цветовая индикация значка в области уведомлений: обычно, напряжённо,
  критически.

### Вход

- **Собственный вход через OAuth с PKCE** (RFC 7636, S256) — делает приложение
  независимым от работающей установки Claude Code. Запрашивается единственное
  право `user:profile`; прямо **не** `user:inference` и **не**
  `org:create_api_key`.
- Без локального веб-сервера: код вставляется вручную, а не принимается через
  перенаправление на `localhost`. Ни одного открытого порта.
- Собственный токен обновляется автоматически. Для токена, считанного у Claude
  Code, это намеренно не делается: вращающийся refresh-токен обесценил бы его
  вход. Отдельные записи в защищённом хранилище.
- Если собственный вход истекает, он удаляется и об этом сообщается, вместо
  молчаливого возврата к Claude Code. Простая же помеха (сеть, 5xx, ограничение
  частоты) оставляет его нетронутым.
- Цепочка запасных источников: собственный вход → сохранённый токен →
  переменная среды → Claude Code. Если API отклоняет источник, запрос переходит
  к следующему.

### Работа

- Интервал опроса не менее 180 секунд, экспоненциальная задержка после неудач,
  серверный `Retry-After` имеет приоритет.
- Только один экземпляр на сеанс входа.
- Автозапуск вместе с Windows, отключаемый.
- Проверка обновлений через выпуски GitHub. Ничего не загружается и не
  выполняется — только сообщается и по желанию открывается страница выпуска.
- Ошибки в действиях области уведомлений больше не завершают приложение, а
  попадают с контекстом в `crash.log`.

### Наблюдения, определившие устройство

- **`claude setup-token` для этой цели не годится.** Такие токены действительны
  и работают с `/v1/messages`, но не несут `user:profile`. Конечная точка
  использования отклоняет их с HTTP 403. Это было исходное допущение проекта, и
  оно опровергнуто.
- **Конечная точка токенов находится на `platform.claude.com`**, а не на
  `console.anthropic.com` — там она отвечает HTTP 404.
- **`User-Agent` обязателен.** Без user agent Claude Code конечная точка
  использования постоянно ограничивает запросы с HTTP 429.
- Собрано с усечением и сжатием: 21 МБ вместо 93 МБ, запуск за 2,3 вместо
  7,2 секунды, 87 вместо 136 МБ памяти. Усечение выигрывает по всем трём осям:
  удалённый код не нужно ни загружать, ни компилировать.

### Известные ограничения

- Пакет **не подписан**. При первом запуске Windows SmartScreen сообщает о
  неизвестном издателе.
- Насколько долго собственный вход переживает длительный перерыв, неизвестно:
  Anthropic не документирует срок жизни refresh-токена.
- Процедура входа использует общеизвестный OAuth-идентификатор клиента Claude
  Code, поскольку Anthropic не предлагает регистрацию собственных приложений.
  Это не официально поддерживаемый путь; он может измениться в любой момент.
- macOS подготовлен, но не реализован.
