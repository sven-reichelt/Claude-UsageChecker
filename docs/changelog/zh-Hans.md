## [0.6.3] – 2026-08-20

### 修复
- **有可用更新时，详情窗口会偏低于屏幕中央。** 该窗口只创建一次并重复使用，因此
  `CenterScreen` 只在首次打开时生效；而更新提示是数秒后由网络请求带来的，会让窗口
  高出约一百像素，并且是向下增长。现在只要内容尺寸变化，窗口就会重新居中。

## [0.6.2] – 2026-08-20

### 变更
- **通知区域图标会说明自身状态。** 未登录时保持灰色；已登录且额度正常时带绿色对勾，
  达到警告阈值时为琥珀色问号，达到严重阈值时为红色感叹号。此前这一切只靠颜色表达。
  每种状态只用一个符号：在十六像素下——任务栏的常见尺寸——两个符号已无法分辨。

### 修复
- **额外额度显示为实际值的一百倍，且单位有误。** API 返回 `used_credits: 2276`，
  这并非 2276 点额度，而是 22.76 欧元——以货币最小单位表示的金额。**货币取自账户**
  ——USD、BRL，视情况而定——小数位数也一并取自响应，因为并非每种货币都有两位。现在
  优先读取 `spend` 字段，它明确说明了自己的数字代表什么。

## [0.6.0] – 2026-08-20

### 修复
- **按模型划分的每周限额未显示。** 拥有 Fable 限额的人在任何地方都看不到它——工具提示、
  上下文菜单、详情窗口都没有——尽管 Claude 自己会列出。原因在于：本应用读取的是
  `seven_day_opus` 和 `seven_day_sonnet` 字段，这两个字段把模型名称写在标识符里。
  如今二者皆为空，而 `seven_day_fable` 这样的字段并不存在。

  该 API 还会以 `limits` 列表的形式给出同样的数值，并在内容中标明模型
  （`scope.model.display_name`）。现在优先读取该列表，旧字段仅作后备。**今后的每一个
  模型都会自动出现**，此处无需改动。详见
  [docs/api-research.md](../api-research.md)。

  通知区域的图标同样会计入这些限额——此前即便某个模型的额度已经用尽，图标仍保持绿色。

### 新增
- **九种语言。** 德语、英语、西班牙语、法语、意大利语、葡萄牙语（巴西与葡萄牙分开）、俄语和
  简体中文。首次启动时，本应用遵循系统语言；可在安装窗口中更改——在那里选择立即生效，且**两个**
  按钮都会采纳——此后也随时可在设置中更改。

  数字、日期和时间的区域格式随语言一同切换：把界面调成法语的人，并不指望在那里看到德语日期。

  **更新日志也一并翻译。** 因此，更新后显示的一览与界面使用同一种语言。英语为原文，位于
  [CHANGELOG.md](../../CHANGELOG.md)；包括德语在内的译文放在 [docs/changelog/](.)。

  产品名与模型名不作翻译：「Claude UsageChecker」「Claude Code」以及来自 API 的模型名称——
  「Fable」在任何语言里都是 Fable。
- **警告阈值与严重阈值可自行设置。** 图标从多高的用量开始变黄、从多高开始变红，现在写在
  设置里，而不再固定于代码中（默认值不变，仍为 75 % 和 90 %）。警告阈值高于严重阈值时会
  被拒绝，而不是被悄悄改正——那样它永远不会生效。
- **更新后显示新增内容一览。** 新版本首次启动时，本应用会显示自上一个运行过的版本以来的
  变化，其中包含被跳过的中间版本。数据来自随程序一同发布的更新日志，无需联网：因此该一览
  在离线时同样可用，并且必然显示与当前运行版本相符的内容。首次安装后的第一次启动不显示。
- **上下文菜单中的「关于 Claude UsageChecker」。** 显示图标、版本、简短说明，并可前往项目
  页面。完整的更新日志也可从那里打开。

### 变更
- **项目语言为英语。** 文档、注释、标识符和测试名称——仓库中的一切，德语界面文本和此前的提交历史
  除外。理由很简单：这是一个公开仓库，找到它的人应当读得懂。德语文档在 [docs/de/](../de/)
  下并行维护。
- 上一次运行的版本会记录在设置文件中（`lastRunVersion`）。这是本应用识别更新的唯一依据——
  可执行文件本身并不知道在它之前运行过什么。

  较早的版本并不认识该字段。从这样的版本升级而来，就没有任何记录；此时由设置文件是否存在
  来判定：它证明本应用已经运行过，于是显示当前版本的新增内容。若没有这一分支，恰恰是引入
  该一览的那个版本什么也显示不出来。
- `MonitorOptions` 不再携带阈值。监视器从未读取过它们：它只获取数值，不作判断。判断只在
  一个地方进行，即 `TrayIconSeverityResolver`，依据用户设置。同一项数值有两处，无异于邀请
  日后拧错旋钮。
- 计算得出的 `PollInterval` 不再写入设置文件。它在那里从未被读取，只是看起来像关于查询
  间隔的第二个说明，可能与第一个相互矛盾。
- **设置窗口不再越出屏幕。** 窗口随内容增长且无法调整大小；在较矮的屏幕上，它会连同
  「保存」按钮一起伸出下边缘。现在有两重保障：按钮行固定在滚动区域下方，无论屏幕多矮
  都保持可见；窗口在布局完成后被测量，若仍然超出便向上移动。仅限制高度并不够——Avalonia
  按窗口打开那一刻的高度居中，而内容是之后才增长的。

### 移除
- **手动输入令牌**已从设置中移除。它对任何人都无用武之地：唯一能粘贴的令牌来自
  `claude setup-token`，而它缺少用量端点所要求的 `user:profile` 权限范围。真正可用的
  令牌——Claude Code 安装的令牌和应用自身登录的令牌——都无需手动输入。早期版本保存的
  令牌仍会被读取，消失的只是添加令牌的入口。理由见
  [docs/api-research.md](../api-research.md)。

### 文档
- **错误报告与功能请求的模板**位于 `.github/ISSUE_TEMPLATE/`，另有 pull request 模板和
  [CONTRIBUTING.md](../../CONTRIBUTING.md)——采用英文，使德语区以外的人也能提交报告。表单
  会询问版本、操作系统、订阅类型和令牌来源，并明确提醒不要粘贴令牌。
- API 调研笔记（[docs/api-research.md](../api-research.md)）记录了新的响应格式，包括哪些
  字段仍未使用以及原因。

## [0.5.0] – 2026-08-19

### 变更
- 安装目标位置改为 `%LOCALAPPDATA%\Programs\ClaudeUsageChecker`，不再是
  `%USERPROFILE%\ClaudeUsageChecker`。前者是 Windows 为无管理员权限的应用预留的位置——
  VS Code 和 Signal 也在那里。用户配置文件的根目录因此保持整洁，毕竟没人会在文档和下载
  旁边找程序。

  **已安装的副本不会自行迁移。** 它们仍从旧位置运行。迁移方法很简单：打开设置并保存——
  若勾选了自启动，就会复制到新位置。旧目录随后可手动删除。

## [0.4.1] – 2026-08-19

### 修复
- 早期版本的解压文件夹残留在临时目录中。压缩后的单文件无法从包内加载其原生库——.NET 运行时
  会将它们解压到 `%TEMP%\.net\ClaudeUsageChecker\<标识>`，而标识取决于内容，因此每个版本
  都会得到自己的文件夹。每次更新约 16 MB，无限累积。现在本应用会自行清理。

## [0.2.0] – 2026-08-19

首次发布。适用于 Windows x64 的独立单文件，21 MB，无需 .NET 运行时。

### 显示

- 来自 `GET /api/oauth/usage` 的 5 小时会话限额和每周限额（总计、Opus、Sonnet）——权威数值，
  而非估算。
- 工具提示显示用量、重置时间和剩余时间。若重置落在另一天，前面会加上星期几；相隔一周以上
  则显示日期——对每周限额而言，仅有时刻会含义不明。
- 上下文菜单列出**所有**已报告的限额。
- 详情窗口带有进度条、重置时间、额外额度（`extra_usage`）以及实际使用的令牌来源。
- 通知区域图标按颜色区分：正常、紧张、严重。

### 登录

- **通过 OAuth 与 PKCE 的自有登录**（RFC 7636，S256）——使本应用不再依赖正在运行的 Claude
  Code。所申请的权限仅为 `user:profile`；明确**不**申请 `user:inference`，也**不**申请
  `org:create_api_key`。
- 不使用本地 Web 服务器：代码由手动粘贴，而非经由重定向到 `localhost` 接收。不开放任何端口。
- 自有令牌会自动续期。对于从 Claude Code 读取的令牌则有意不这么做——轮换的 refresh 令牌会
  使其登录失效。二者在安全存储中分开存放。
- 自有登录一旦过期，会被移除并加以说明，而不是悄悄退回到 Claude Code。单纯的干扰（网络、
  5xx、限流）则不会影响它。
- 回退链：自有登录 → 已保存的令牌 → 环境变量 → Claude Code。若 API 拒绝某个来源，请求便
  转向下一个。

### 运行

- 查询间隔至少 180 秒，失败后按指数延长等待，服务器的 `Retry-After` 优先。
- 每个登录会话只运行一个实例。
- 随 Windows 自启动，可关闭。
- 通过 GitHub 发布检查更新。不下载也不执行任何内容——只作提示，并可按需打开发布页面。
- 通知区域操作中的错误不再终止应用，而是连同上下文写入 `crash.log`。

### 影响设计的发现

- **`claude setup-token` 不适用于此目的。** 这类令牌是有效的，可用于 `/v1/messages`，但不带
  `user:profile`。用量端点会以 HTTP 403 拒绝它们。这曾是本项目最初的假设，现已被推翻。
- **令牌端点位于 `platform.claude.com`**，不再位于 `console.anthropic.com`——后者返回
  HTTP 404。
- **`User-Agent` 是必需的。** 若没有 Claude Code 的 user agent，用量端点会以 HTTP 429 长期
  限流。
- 以裁剪加压缩方式构建：21 MB 而非 93 MB，启动耗时 2.3 秒而非 7.2 秒，占用内存 87 MB 而非
  136 MB。裁剪在三个方面都占优——被移除的代码同样无需加载和编译。

### 已知限制

- 该软件包**未经签名**。首次启动时 Windows SmartScreen 会提示发布者未知。
- 自有登录能挺过多长时间的闲置尚不清楚——Anthropic 并未记录 refresh 令牌的有效期。
- 登录流程使用 Claude Code 公开已知的 OAuth 客户端 ID，因为 Anthropic 不提供注册自有应用的
  途径。这并非官方支持的方式，随时可能改变。
- macOS 已做准备，但尚未实现。
